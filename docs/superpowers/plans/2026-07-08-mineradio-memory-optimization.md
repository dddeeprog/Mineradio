# Mineradio 内存优化升级计划

## 目标

以 `develop/mineradio-maintenance` 为底座，分批降低在线播放器和本地库融合后的常驻内存、渲染峰值和大列表 DOM 压力，同时保留现有播放、Folia 舞台、弹幕和本地库能力。

## 第一批：低风险内存预算基础

- 新增统一内存缓存工具，覆盖缓存计数、对象缓存裁剪和队列窗口计算。
- 扩展运行时性能快照，记录播放队列、本地库、弹幕、Folia 主题和本地节奏缓存规模。
- 给弹幕、Folia 主题、本地节奏缓存加入后台/深度后台裁剪预算。
- 本地库导入后不再额外持有完整扫描结果和歌曲副本，避免大文件夹双份常驻。
- 队列面板和底部迷你队列改为窗口化渲染，避免上千首队列一次性生成完整 DOM。

## 第二批：媒体资源生命周期

- 给封面、深度图、弹幕纹理和本地媒体数据 URL 加入引用释放路径。
- 将本地封面和音频元数据读取改成按需、分块、可过期缓存。
- 建立播放切歌、后台、最小化、退出本地库时的资源释放检查点。

## 第三批：大列表与搜索结果分层渲染

- 将搜索结果、歌单详情、本地库结果和播客列表统一接入可复用窗口渲染。
- 对动画入口增加可见区域限制，避免隐藏面板仍触发布局和动画。
- 对超大本地库增加分页搜索和按需排序，避免一次性复制全量数组。

## 第四批：3D 与 Folia 预算

- 为 Three.js 纹理、几何体、renderLists 和 Folia iframe 生命周期建立显式预算。
- 在后台 release 模式下冻结或释放低优先级视觉层，只保留播放必要状态。
- 增加 renderer.info、JS heap、缓存规模的诊断面板入口，便于对比优化前后数据。

## 验收方式

- 每批必须包含可回归测试或静态 smoke 断言。
- 每批执行 `npm run check`、`npm run test`、`git diff --check`。
- 打包或长时间播放前后记录 `window.__mineradioPerfSnapshot()` 的缓存规模和 heap 变化。
