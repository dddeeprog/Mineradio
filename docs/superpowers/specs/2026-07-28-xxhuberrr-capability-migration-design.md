# XxHuberrr Mineradio 能力融合设计

## 目标

以 `codex/unified-player` 为唯一功能底座，将 `XxHuberrr/Mineradio@4abaa19` 中已确认的在线能力、播放增强、Cuefield、视觉、完整桌面、Wallpaper Engine、性能治理及更优工程实现分批迁入，同时保留当前 Mineradio 的 Folia 原生歌词、本地音乐库、安全更新、发布验证和既有视觉体验。

本设计不进行整仓覆盖，也不把远端 `public/index.html`、`server.js` 或模块加载顺序直接替换到当前分支。每一批迁移都必须形成独立、可测试、可回退的功能切片。

## 已确认范围

### 第 1 类：限定接入

仅接入以下能力：

1. 增强网易云专辑详情、专辑收藏、歌单订阅、评论点赞和评论创建。
2. 新增网易云、QQ、酷狗、汽水、Spotify 五平台统一搜索。
3. 新增平台能力声明接口。
4. 新增账号维度的收藏、会员和音源缓存。
5. 新增跨平台收听统计和最近播放上报。
6. 增强多平台登录中心、登录引导、外部登录窗口、Cookie 手动导入和退出流程。

明确排除：

- 酷狗、汽水和 Spotify 的完整播放链路。
- 汽水音频解密器及本地会话自动发现。
- 酷狗、汽水和 Spotify 的专辑收藏、歌单写入、评论写入等完整平台操作。
- 用未验证的第三方播放路径绕过平台能力声明。

### 第 2–7 类：完整接入

- 搜索、首页、歌单和内容列表体验。
- 播放事务、音源回退、音频图恢复、输出设备、无缝播放和淡入淡出。
- Cuefield AutoMix。
- Sonic Topography 及不覆盖 Folia 的视觉、歌词增强。
- 完整桌面模式和 Wallpaper Engine。
- 性能、缓存、系统内存和后台释放治理。

依赖第 1 类已排除能力的功能必须通过能力声明降级。例如播放回退只在当前支持播放的网易云和 QQ 之间执行；五平台搜索可以展示酷狗、汽水和 Spotify 元数据，但不能伪装成可直接播放。

### 第 8–9 类：择优融合

接入远端更优部分：

- 安装目录归属标记、危险路径校验、已知文件清理和不安全旧卸载器禁用。
- 稳定用户数据根目录和分层缓存目录迁移。
- Spotify PKCE 无客户端密钥登录。
- 内测版独立构建配置。
- 新功能的第三方来源、许可证和固定版本记录。
- 按功能切片的前端模块化、纯核心模块、针对性测试和桌面诊断脚本。

保留当前更优部分：

- `desktop/ipc-auth.js`、`desktop/navigation-guard.js` 和 `server/security.js` 的集中安全边界。
- 当前更新下载、摘要校验、镜像约束和发布产物验证。
- 当前 Node Test、Playwright、依赖审计和发布检查入口。
- 当前 Folia、本地库、天气、弹幕和桌面歌词模块。
- `English-worse/Mineradio` 的发布归属。

依赖升级只在 `npm audit --omit=dev`、CommonJS 加载测试和全量回归通过后进行，不直接照搬远端锁定版本。

## 平台能力模型

服务端提供统一、只读的能力声明：

```js
{
  provider: 'netease',
  auth: ['qr', 'cookie', 'external-window'],
  search: true,
  playback: true,
  sourceMatch: true,
  albumDetail: true,
  albumCollect: true,
  playlistSubscribe: true,
  playlistWrite: true,
  commentsRead: true,
  commentsLike: true,
  commentsCreate: true,
  recentPlayReport: true,
  listenDurationReport: true
}
```

首版能力矩阵：

| 平台 | 搜索 | 登录中心 | 播放 | 收藏/写入 | 评论写入 | 收听上报 |
| --- | --- | --- | --- | --- | --- | --- |
| 网易云 | 是 | 二维码、Cookie、外部窗口 | 是 | 是 | 点赞、创建 | 支持时提交平台并保留本地统计 |
| QQ | 是 | Cookie、外部窗口 | 是 | 保留现有能力 | 否 | 本地统计，平台能力按实际声明 |
| 酷狗 | 是 | Cookie、外部窗口 | 否 | 否 | 否 | 仅记录搜索来源和后续匹配结果 |
| 汽水 | 是 | Token/Cookie、外部窗口 | 否 | 否 | 否 | 仅记录搜索来源和后续匹配结果 |
| Spotify | 是 | PKCE、外部窗口 | 否 | 否 | 否 | 仅记录搜索来源和后续匹配结果 |

前端不能根据平台名称硬编码按钮。收藏、评论、播放和歌单操作都必须读取当前能力声明；不支持的命令不显示，能力暂时不可用时显示不可用状态而不是尝试请求。

## 核心架构

### 平台基础层

新增独立的平台注册表、账号作用域、缓存和搜索聚合模块。现有网易云、QQ 路由作为适配器接入，不重写其已经稳定的播放实现。

统一搜索返回标准歌曲结构：

```js
{
  provider: 'spotify',
  sourceId: '...',
  title: '...',
  artists: [{ id: '...', name: '...' }],
  album: { id: '...', name: '...' },
  cover: 'https://...',
  durationMs: 0,
  playable: false,
  matchHints: {},
  capabilities: { playback: false }
}
```

聚合搜索允许单个平台失败。响应包含成功结果、逐平台分页状态和错误列表；一个平台超时不能让整次搜索失败。跨平台同曲可以建立展示分组，但必须保留每个平台原始记录和来源标识。

### 账号与缓存

账号缓存键固定为：

```text
provider + accountFingerprint + namespace + resourceKey
```

`accountFingerprint` 由平台账号 ID 或登录凭证摘要生成，不能保存原始 Cookie、Token 或 Client Secret。登录成功、退出和账号切换必须原子更新账号上下文；退出时只清理对应账号的收藏、会员和音源缓存，不影响其他账号。

桌面端采用稳定用户数据根目录，并将 Chromium 会话、歌词、节奏图、更新包、平台缓存和本地库元数据分目录保存。迁移器只移动 Mineradio 明确拥有的文件，不能扫描或删除未知内容。

稳定用户数据根目录必须在首个持久化平台缓存写入前完成。账号凭证不能写入前端 `localStorage`；桌面环境优先使用 Electron `safeStorage` 加密落盘，不可用时必须显式报告降级状态且限制文件权限。OAuth 只申请当前能力所需的最小 scope，Spotify 首期不能申请收藏或歌单写入 scope。

Cookie、Token、OAuth code、refresh token 和完整账号指纹不得进入普通日志、错误响应、性能快照或统计记录。登出必须清除对应凭证、专用 session partition、内存中的请求去重项和该账号作用域缓存；账号切换必须等待旧作用域失效后才能发布新账号状态。

### 播放与统计

播放增强统一进入一个事务状态机：

1. 保存当前队列、歌曲、进度、音量和音频图状态。
2. 根据能力声明选择可播放提供方。
3. 获取地址、连接音频图并确认开始播放。
4. 成功后提交新状态；失败则恢复旧状态并尝试下一个受支持来源。
5. 所有来源失败时保持队列和当前歌曲，不制造半切换状态。

统计日志同时记录 `catalogProvider`、`playbackProvider`、`resolutionMode` 和 `completeness`。只有实际进入 Mineradio 播放状态机并产生有效播放时长的歌曲才能生成收听事件；仅在酷狗、汽水或 Spotify 中完成搜索不能计为收听。当这些平台的搜索结果匹配到网易云或 QQ 播放时，前者只作为 `catalogProvider`，真实播放平台写入 `playbackProvider`，并将 `resolutionMode` 标记为 `matched-provider`。

本地统计始终可用，且明确区分 `complete`、`partial` 和 `unsupported`。平台最近播放或时长上报只发送给声明相应写能力的真实播放平台，不能向仅提供元数据的平台伪造播放记录。所有上报使用幂等会话 ID，防止暂停、恢复或重试造成重复提交。

### 登录中心

登录中心按能力声明渲染平台及登录方式，统一处理：

- 二维码、Cookie、Token 和 Spotify PKCE。
- 受 `ipc-auth`、导航白名单和权限策略保护的外部登录窗口。
- 登录完成后的账号指纹建立、状态刷新和缓存切换。
- 退出后的凭证清理、窗口关闭、缓存失效和界面刷新。

任何外部登录窗口都不能获得任意 IPC、文件系统访问或不受限制的导航权限。

## 模块边界

新模块必须采用当前项目可直接由 Node Test 加载的 UMD 或 CommonJS 形式，并保持单一职责：

- 平台注册表只描述能力，不执行网络请求。
- 提供方适配器只负责请求和标准化。
- 搜索聚合器只负责并发、超时、分页和部分失败。
- 账号缓存只负责作用域、TTL、容量和失效。
- 播放事务只负责状态提交/回滚，不操作界面。
- UI 模块只消费标准模型，不读取原始平台响应。
- 桌面运行时只通过已授权 IPC 暴露能力。

当前 `public/index.html` 仅保留装配和现有尚未拆分逻辑。本次触及的新功能必须优先进入独立文件，不能继续扩大单文件职责。

## 错误处理与回退

- 平台搜索超时返回部分结果及平台错误，不清空已成功结果。
- 登录凭证无效只重置对应平台和账号作用域。
- 缓存读取失败回退网络请求；缓存写入失败不阻断播放。
- 播放事务失败恢复原队列、进度和音频图。
- Cuefield 分析或执行失败立即回到普通切歌。
- Sonic、完整桌面或 Wallpaper Engine 初始化失败时关闭对应功能，不影响主播放器。
- 稳定目录迁移和卸载脚本遇到未知文件必须停止删除。

每个大功能在迁移期间都有显式功能开关。单批验收后再默认启用，最终收口时删除无用的双实现。

## 测试与验收

所有行为修改采用 TDD，先运行并确认失败测试，再写最小实现。

每批至少执行：

```powershell
npm run check
npm test
git diff --check
```

涉及界面的批次补充 Playwright 固定夹具和桌面/移动窗口截图；涉及发布的批次补充：

```powershell
npm run test:visual
npm run audit:prod
npm run verify:artifacts
npm run build:win:dir
```

关键验收条件：

- 切换任意账号后不能读取上一账号的收藏、会员或音源缓存。
- 五平台搜索单个平台失败时仍返回其他平台结果。
- 不支持播放的平台不会出现可播放按钮或进入音源回退队列。
- 连续失败的播放切换不会破坏当前队列和音频图。
- AutoMix、Sonic、完整桌面和 Wallpaper Engine 都能独立关闭并恢复基础播放器。
- 新模块测试加入现有测试入口，不建立互相冲突的第二套测试体系。
- 安装和卸载只能操作有 Mineradio 归属标记的已知目录与文件。

## 来源与许可

远端来源固定为 `XxHuberrr/Mineradio@4abaa19`。迁移 Cuefield、Sonic、完整桌面、Wallpaper Engine、安装器或其他实现时，必须在改编文件头和 `NOTICE.md`、`docs/VENDOR_MANIFEST.md` 中记录原文件、commit、许可证和改编范围。

当前仓库的 Folia AGPL 来源声明继续保留。迁移不得删除或弱化任何既有第三方声明。
